# 分镜与人物生成运行规则

版本：2.6

更新时间：2026-10-10（Asia/Shanghai）

用途：个人 Skill 保存接口不可用期间，可直接读取并执行的备用规则入口。此文档不是已安装的个人 Skill。恢复安装后，用本文件与已验证的源文件核对规则，不用旧缓存覆盖新版。

## Rui-Skills 统一服务器使用许可（2.6）

用户选择公网服务器与HTTPS域名统一授权。每台机器使用服务器单独发放的凭证，每次视频任务先按[统一授权流程](../rui-skills/references/local-verification.md)执行 `node scripts/local-gate.mjs verify`，实际成功才继续；未配置、设备停用、拒绝、超时、断连、证书异常、无法运行或版本未批准均停止。禁止本机自建替代服务、离线许可、客户端自动批准版本或使用备用规则绕过。设备与版本管理仅在服务器端执行，人物设定图技能独立。接口配置与维护可以执行；文字分镜仍依赖执行助手遵守检查，不能宣称可编辑源码提供不可绕过保护。

## 先按任务隔离规则（2.3）

用户要求人物设定图与真人剧视频提示词分开执行。本文件同时保存两类历史规则，但不能整份混用：

- 视频分镜使用 `$rui-skills`，读取对应的视频、剧情与连续性规则；不加载人物三视图、造型补全和美术资产设计模板。已有角色/场景图只作为资产输入。
- 人物设定图使用独立技能 `$character-turnaround-from-image`；文字人物与场景设计仅在用户明确委托该产物时进入[独立资产设计流程](../rui-skills/references/asset-design-workflow.md)。本文件的人物三视图、参考图肤质修复等静态图像规则只适用于该任务。
- 同时要求两者时分两份提示词与两套检查，视频仅引用用户指定资产及已确定状态，不复制设定图的服装设计、图外补全、拼版和中性照明要求。
- 视频优先使用用户的角色/场景引用；只描述辨认、动作、连续性或明确修改所必需且有来源的细节。不自拟衣服颜色款式、装修颜色、家具或建筑结构；未知且无关的细节保持未指定。
- 视频交付前内部检查必要的环境交代、特写/虚化/暗部对空间线索的影响、手机与人物和摄影机位置、拉焦与换机位区别、监控/手机/插叙来源，以及轴线、动作和光向。按剧情修正后交付，不强制每镜加全景、纵深或运镜，不以增强空间感为由重设场景。

## Rui-Skills 名称与制作扩展

主技能界面名称为 **Rui-Skills**，文件夹及调用标识为 `rui-skills` / `$rui-skills`。旧 `write-15-second-storyboards` 是历史名称；本次只更改 skill 名称与目录，GitHub 仓库 URL 保持不变。独立人物技能 `$character-turnaround-from-image` 继续可单独使用。

默认每组 0–30 秒，镜头连续覆盖，不以修改标题或倍速把旧 15 秒内容冒充 30 秒。视频模型的单次生成上限另行核对；必要时在镜头边界拆分生成批次，并保留在整组中的时间映射与末首帧衔接。

整剧制作新增按需模块：小说改编大纲、角色与音色设定、场景及叙事道具、美术状态变体、剧本节拍与时长、结构化分镜和制作报告。主技能中的 `references/production-workflow.md` 与 `references/production-data.md` 是执行入口；各模块随技能分发，不依赖其他已安装 skill。简单口头剧情继续直接写分镜，不强制补齐全套项目数据。

角色参考图在独立资产任务中支持锚点、独立视角、单张重出、版本与过期管理；流程见人物技能内的 `references/character-assets.md`。横向大头照加正侧背拼版、浅灰背景与参考图肤质要求仅在设定图任务生效。结构化检查不能代替实际图像与视频检查。

## 真人剧与漫剧分别执行

Rui-Skills 主入口先选模式：真人剧 `live-action` 读取 `references/live-action-workflow.md`，漫剧 `comic` 读取 `references/comic-workflow.md`。当前用户选择优先于项目配置；没有指定且无项目模式时沿用真人剧默认。漫剧默认2D动漫，用户指定其他画风时服从指定。两种模式均默认30秒、中文、无BGM/字幕。

完整项目在根目录 `production.json` 保存模式和可选风格；需要两个版本时分别建子目录，保留各自的设定、参考图和输出。大纲、剧情、台词来源与连续性方法共用，实拍摄影和克制微表演适用于真人视频；漫剧沿用既定画风与动画规范。真人/漫剧是视频风格选择，不能据此激活人物设定图规则；静态图像规则仍按独立任务读取。

`production.mjs check/report/export-text` 支持 `--mode live-action|comic`；根据模式显示报告、选择默认统一提示词与约束。切换模式不会自动转换原有资产或自定义统一提示词，应先完成目标模式资料。结构/文本验收与实际图像/动画验收分别记录。

## 真人剧的ANERNEQ光影参考

用户确认「北极之息」为Higgsfield《ANERNEQ》。真人剧场景提示词读取[画面观察、光影规则与原创模板](../rui-skills/references/anerneq-lighting.md)：默认使用有来源的局部照明、阴影层次、材质差异与跨镜光源连续性，按本场夜外、暗室、日光、阴天或现代室内迁移选择拍法。人物移动和手部遮挡改变受光面；正反打保持光源在场景中的位置。昼夜、天气、已有光源和用户风格优先；不将所有场景转成冷蓝雪地夜景。中性人物参考图与漫剧继续使用各自规范。

依据2026-10-06对[官方公开播放版](https://higgsfield.ai/@higgsfield.studio/projects/anerneq)约20分02秒全时间线的1202张逐秒画面及四段4秒/4fps密集帧检查；未检查音轨或被公开版遮挡的内容。视觉观察与原创反推方案分别标记，不声称得到影片原始提示词、LUT或设备参数。实际生成效果待另行验证。既有ARRI/Zeiss摄影基准来自用户偏好，不是本片参数。

真人剧文本导出的默认提示词与约束同步包含已有光源、受光面和曝光连续性原则；自定义`storyboard.unifiedPrompt`优先，源场景、人物、台词和时长不改写。

## 调用方式与版本选择

新对话可直接说：“读取《分镜与人物生成运行规则》的最新版，按它完成我的任务，并从本次调用开始记录。”也可以在任务中附上或选中本文件。本对话中已经读取的规则继续适用。

执行者先实际读取本文件的最新可用版本。仅凭文件名、聊天记忆或旧 Skill 名称不能声称读取了最新版。多个同名文件时，优先已关联的文件身份；无法确定时按版本和更新时间辨认，不合并未知来源。用户本轮明确指令优先于本文件，项目特殊设定不能误当通用规则。

每次更新替换同一份规则文件并保留版本历史。记录中写明实际读取的规则版本。此入口不要求 GitHub 连接，也不能保证旧 Skill 选择器自动载入它；没有载入本规则的其他聊天不受此流程覆盖。

## 每次调用：开始记录、检查结果、更新规则

适用于剧本理解、分镜、提示词、生图、修改、检查及失败或中断的调用。记录不等待用户反馈，不等待生成成功，也不等待出现新经验。

1. **开始。**进入任务后、剧情分析和生成前，建立唯一记录，状态为 `started`，写入真实时间、任务摘要、规则版本及调用类型。先保存起始记录，再进入创作。有配套记录脚本时可使用；没有脚本时创建同样结构的 JSON。生成编号与时间必须来自实际运行，不补造。
2. **保存。**默认使用可用的持久文件保存能力。已有文件身份后，后续追加阶段内容并更新同一记录。临时工作区只作工作副本；确实没有持久写入能力时标为 `persistence_pending`，继续不受影响的创作，并明确尚未保存。
3. **过程。**记录资料实际读取范围、采用的关键规则、生成或编排尝试、可观察结果、检查、修订及失败。较长阶段、重要变更和中断时保存检查点。只记必要的脱敏过程摘要和结果，不保存隐藏推理、完整聊天、私人剧本、图片、凭据或原始工具输出。
4. **主动检查。**即使用户没有反馈，也比较目标、提示词与实际结果。没有查看图片或视频时，视觉验证填 `not_run` 或 `unavailable`；文件能打开、提示词格式正确不能替代生成效果通过。
5. **复盘。**区分用户明确要求、观察事实、待验证假设。提炼有适用范围、依据和检查办法的可复用规则；没有新规则就记录 `no_new_rule`，不为制造“学习成果”虚构经验。失败方法保留失败状态。
6. **写回。**先去重，再修改本文件对应规则、模板与检查项，更新版本和变更依据，替换同一持久文件。新要求不能只躺在日志中。个人 Skill 的安装保存若仍失败，另外标为 `skill_update_pending`，保留可用规则入口；两项状态分别报告。
7. **结束。**记录 `completed`、`failed` 或 `interrupted` 和真实结果，再保存同一记录。被取消或中断的工作不能记成已完成。

记录至少包含：`schema_version`、`id`、`recorded_at`、`timezone`、`skill`、`task_summary`、`rules_version`、`status`、`events`、`lessons`、`validation`、`persistence`、`github_sync`。每个事件有时间、阶段和简短摘要。每条经验有类型、证据、适用范围与验证状态；类型采用 `user_requirement`、`verified`、`pending_validation` 或 `no_new_rule`。历史补记必须注明 `backfilled` 和真实补记时间。

这些更新维护可读取的工作方法和经验文件，不修改模型权重，不等于持续监听后台或自动记住所有聊天。

## 分镜：先理解剧情与连续性

直接交付完整成稿，沿用用户指定时长和格式。默认以连续 30 秒为一组；用户指定其他时长时服从要求，可分成衔接的组，但总时间要完整连续，不留空、不重叠。

先实际读取指定剧情文档。整剧或跨场任务按集、场累积资料，不能只看摘要便声称理解整剧。分批收到的剧本明确已读范围与版本，未收到部分保持待确认。只有一句剧情时按已给信息展开，不强制索要完整剧本。技能规则中只保存方法；项目资料另行保存。

最少维护以下资料：

| 资料 | 必备内容 |
| --- | --- |
| 场次索引 | 集号与场号、内外日夜、地点、人物、剧情目标、相邻场次、来源 |
| 人物状态 | 身份、外貌、服装发型、知情范围、情绪目的、进出场与起止姿态 |
| 表演依据 | 触发信息、关系与顾虑、潜台词、可见反应、反馈时点、事实或推断 |
| 场景空间 | 固定入口、门窗、家具、光源、路线、摄影轴线与机位 |
| 场景出场 | 场景 ID 与别名、全剧剪辑顺序的首次登场、已读次数、全剧频率与来源 |
| 道具状态 | 归属、握持手、位置、开关、数量、变化镜头 |
| 镜头交接 | 上镜末帧与下镜首帧的人数、站坐、面向、视线、手势、道具、声音和光照 |
| 风险 | 版本冲突、证据不足、禁止项与必要假设 |

用户最新明确修订优先，其后核对最新版剧本和参考图。不得借后续剧情使人物提前知情，不擅改台词、人物关系或关键动机。

## 场景在全剧中的展示规则

先按观众实际看到的全剧剪辑顺序核对，而不是只看本集或故事时间。统一同地点别名，不把本集首次出现当成全剧首次。频率依据完整剧本或用户设定判断，不自定次数门槛；未读部分不得当成零次。

| 场景状态 | 默认镜头设计 |
| --- | --- |
| 全剧首次出现 | 默认安排大全景与移动氛围交代，可合为一镜，展示空间规模、入口、通道、人物位置、光源和现场氛围 |
| 已出现但全剧出场不频繁 | 优先动作特写，用已有真实动作带出辨识细节，如手推门、鞋跨门槛、拿起已有物件 |
| 已出现且频繁复用 | 通常直接进入人物动作或关系镜头，利用熟悉背景锚点维持辨识 |

首次出现规则优先：即使整剧只出现一次，首次登场仍默认安排大全景与移动氛围交代。后续低频再现才优先动作特写。动作特写写清起因、接触、变化、声音和切点，不能用静态环境空镜替代，也不能为展示细节新增无因动作、道具或剧情。

移动氛围镜头写起点、路径、终点和进入人物戏的切点；大全景与移动可合为一镜，长度服从对白和动作所需时间。用户本轮指定景别或禁止大全景时优先遵守。

每次分镜包括单场片段都执行此判断，交付前逐场核对出场依据、对应镜号和用户例外；缺失则先修正。详细标准见[场景展示规则](../rui-skills/references/script-continuity.md#场景展示镜头全剧出场顺序与频率)。不固定每集先拍运动主体，也不把开场钩子当作省略首现空间交代的理由；已指定固定监控则保留其固定机位。不强制每镜加全景，不等于可以跳过首次场景展示。

## 人物表演与反应镜头

从人物当场目的、顾虑、关系、知情范围、潜台词和情绪转折推导少量可见动作，不等待用户逐条指定。写成“触发信息 → 短暂停顿或本能变化 → 视线或表情 → 身体或手部动作 → 等待反馈”，每镜选最有效的细节，不把整条链机械塞进所有镜头。

眼神必须有对象和时序：先看哪里、何时转向谁、是否回避、对方回应后如何变化。“震惊、试探、真诚”须落实为行为。持续看向某人指目光停留在对方脸上，不等于抓住对方、瞪眼或不眨眼；不以眼神变色、冒火代替表演。

按姿态和空闲手安排动作。既定站立状态不擅自改成坐姿；握手、拿东西或驾驶时，不凭空增加需要占用同一只手的动作。背景人物只在确实看见或听见触发信息后反应，不全员同时做相同夸张表情。关键微动作选能看清的景别，计入动作与反馈时长。

**已指定的办公区片段约束，仅用于对应剧情：**

- Lorenzo 宣布时，员工有偷偷看的眼神：保持合理头部朝向，眼睛短暂侧瞟、接收旁人的目光，再收回或压低视线；避免夸张扭头、翻白眼或无因看摄影机。
- Joanna 羞辱对方后，安排现场其他人的震惊反应镜头：短暂迟滞、呼吸停顿、眼睑或唇部轻微变化，反应发生在听见台词之后；人物可有不同强度与先后。
- 对应场次所有人保持站立。此条件不能自动变成所有其他场次的站立要求。

## 分镜编排与交付

先锁人物、地点、台词、道具、起止状态和本轮修改范围。每组有一个清楚的戏剧动作；根据真实语速、停顿和反应分配时间，不机械平均。对白装不下时调整镜头或说明所需时长，不能暗删。

统一提示词一次写清画幅、影像质感、摄影基准、场景坐标、光源与曝光、色调、日夜天气、人物与道具连续性、声音。优先继承用户参数；未指定时可采用常用基准：9:16，ARRI ALEXA 35 Open Gate，Zeiss Master Prime 35/50/75mm，24fps，180°快门，T1.8–T2.8。规格服从实际拍法，不把它们当成所有场景的事实。

默认真实克制、自然肤色和场景灰度，不自动添加商业广告轮廓光、重青橙调或金色滤镜。默认无音乐/BGM/字幕；保留剧情需要的自然环境音、动作音和对白。

每镜给时间、景别、机位和主体位置、焦距与光圈、表情和视线、动作链、环境、运镜与切点。位置以门、桌、通道等固定实物为坐标，画面左/右只作补充。动作写清起因、实施、接触或变化、反应和新状态，避免瞬移、无因换手、道具凭空变位。

建议行文格式：

`0–3秒【中近景｜平视侧后机位｜50mm，T2.0｜固定后轻推】`后接完整画面、人物动作、对方反馈、背景光线与切点，依次覆盖到要求的总时长。实际交付不留“人物……先……”等占位符。用户给了示例格式时优先沿用。

多人预排先确定谁行动、谁看到或听到、谁反应、谁移动、新站位，跟踪进出画与遮挡。反打检查轴线、朝向、视线高度、人数和光向；有意越轴必须用中性镜头、可见跨越或重建方位解释。过肩镜头的同一对方不能同时出现在前景肩部与后景。

多组分别保留足够身份和场景锚点，让单组复制使用时可独立执行；进入和退出状态相接。修改只覆盖用户要求的范围，不自行加剧情、台词、接触或关系变化。

交付前检查：身份、服装、发型、伤痕与湿度；站坐、手势、重心和道具；空间、轴线、方向、遮挡与人数；日夜、光源、对白和动作音；时间总长与跨镜衔接；首现和频率判断的依据。无法从来源确定的关键冲突说明最小必要假设，同时完成不受影响部分。视频生成后另做实际逐帧检查，不承诺提示词能完全消除生成误差。

## 人物设定图：身份与版式

这是独立静态资产流程，不自动拆成 30 秒视频。

有参考图时先实际看图，只用当前指定人物锁定身份，记录可见的脸部结构、年龄感、发型、身形、服装和配饰。不可见的侧背、下装和鞋子保守补全并标明推断，不借历史人物的脸，不把低清图中看不清的细节当事实。

保持眼距、眉眼关系、鼻翼鼻尖、唇形、中庭、下颌与下巴、发型和年龄感，不自行美化成模板脸。多张同一人物图片时指定主图锁身份，其余只辅助可见角度与衣饰。无参考图且用户明确要求虚构人物时，先按要求建立同一角色的固定描述，再在所有视图一致复用；不声称参考了真实照片。

默认横向一张资产图：左约 42% 为正面头肩大头照；右约 58% 依次正面、严格 90° 侧面、真正背面三张全身。三人等高、头脚完整、脚底同一水平线，身份、比例、衣饰、发型、相机高度和光线一致。自然站姿，手臂放松，侧面不改成三分之四，背面不回头。

中性浅灰无缝背景、中性白平衡、低饱和、克制对比。头照用等效 100–135mm 正面平视人像透视；大型柔光在前左约 20–30°、略高眼线，弱填充保留浅影；全身保持同机高和近似正交弱透视。参数是可用基准，服从用户明确风格。

用户要图时调用可用生图工具，有参考就实际传入参考；用户只要提示词时给已填好的完整提示词。若可查看结果，检查同一人、版式、严格侧面、真正背面、头脚和衣饰一致；按真实可见缺陷修订。单张参考无法证明不可见角度，不能承诺百分之百锁脸。

## 真人肤质：自然尺度与局部差异

真实不等于纹理越多越好。默认额头符合人物年龄、自然较平滑，毛孔是细小、低对比、不规则点状或浅凹结构；鼻翼、面颊和额头的密度与尺度有差异。正常观看距离不应看到密集连绵线条覆盖全脸。

保留参考人物已有的痣、雀斑、真实年龄或表情细纹、眼周细节和唇纹；不为了“真实”新增斑点、痘疤、皱纹、衰老、肤色改变或脸型变化。近景有少量自然细绒毛和细微纹理；全身远景只表现合尺度的肤色和明暗，不强行放大毛孔。

采用干爽自然的哑缎质感、柔和散射、细微局部肤色变化和受控柔和高光。鼻尖和颧骨可有少量弱反射；不油亮，也不压成无体积的绝对哑光平面。眼睛、睫毛、眉毛、眼睑和唇线清晰，柔光不等于抹掉皮肤结构。

明确排除摩尔纹式干涉纹、重复波纹、交叉网纹、指纹沟槽、织物或皮革压纹、整脸毛孔贴图、锐化光晕、强 HDR 微对比和粗颗粒。不能以密集纹路或雕刻感替代真人皮肤，也不能以消除伪纹理为由把脸磨成塑料。

正向肤质控制：

`photographic human facial skin, naturally smooth forehead appropriate to age, discreet irregular dot-like pores only where visible at this scale, subtle low-contrast organic skin detail, region-specific texture, realistic gentle shading and local skin-tone variation, genuine age-appropriate expression lines and fine lip detail, natural satin-matte finish with restrained soft highlights, clear eyes, preserved facial identity and age`

负面肤质控制：

`moire-like skin pattern, repetitive wavy lines, crosshatched skin, fingerprint-like ridges, woven mesh skin, embossed leather texture, all-over wrinkle overlay, synthetic pore map, oversized or oversharpened pores, gritty noise painted onto the face, plastic or waxy skin, AI beauty smoothing, oily glass skin, featureless flat matte face, invented blemishes, altered age or skin tone, identity drift`

有独立负面栏时单独提供，否则把关键约束写进主提示词。不编造跨平台通用的参考权重或 Face ID 百分比。

## 肤质修正与效果验证

编辑时保留身份结构、年龄、发型、服装和构图，但不要求逐像素复制已经出错的肤质。必要时重建受影响表面。查看大头区域与合理尺度的局部，检查额头、面颊、鼻翼、下巴和颈部是否仍有重复线纹，以及是否磨皮、油亮或身份漂移。

定向修改仍保留异常纹路时，记录失败并改变策略，例如重新生成受影响区域；不能反复堆叠同一套“真实毛孔”形容词后宣称成功。只检查文本不能证明图像已修复；只有实际看过并符合目标的结果才标为视觉通过。

此前韩女人物设定图的几次编辑仍有异常线纹，不能把它们写成修复成功案例。本文件的肤质控制是明确要求与待持续验证的生成方法，不是保证每次出图合格。

## 当前保存故障与恢复办法

已观察到：个人技能源文件本地校验通过；GitHub 文件写入与读取核验正常；个人 Skill 保存曾先返回推送成功，但随后后台重建删除目录，后续保存返回 HTTP 422。现有返回没有给出具体校验理由。因此不能认定是用户生成要求违规，也不能认定某个字段一定是根因。

当前采用：读取本文件 → 起始记录先保存 → 完成任务并检查 → 同一日志追加 → 有依据的新规则写回本文件。旧 Skill 安装状态单独保留为待恢复，不把规则文件可用称作原 Skill 已恢复。

恢复原入口时，核对最新源文件及本规则版本，按技能创建流程校验和保存；推送返回成功后，还须读取后台最终保存的文件，确认目录与关键规则没有消失。仅当后续调用确实读到新版，才报告恢复。不要删除唯一可用备份，不做强制推送，不无限重复同一失败请求。

如果需要向产品团队反馈，可使用应用的反馈入口，附“个人 Skill 保存 HTTP 422；本地校验通过；曾推送成功后目录被后台重建删除”的脱敏摘要。不得未经用户明确要求自动发消息或发布问题。
