# Rui-Skills

Rui-Skills 提供分别使用的 **真人剧** 与 **漫剧** 制作流程，可将用户提供的剧情、小说或剧本整理为大纲、人物与美术资料、剧本及分镜，也可独立处理人物三视图和角色参考资产。当前 **v2.0.1** 默认交付精简、可独立使用的分镜提示词与 Word 文档；时长由对白和动作决定，**30 秒是每组上限，不要求填满**。

界面名称：**Rui-Skills**。调用标识：`$rui-skills`。

本文依据 [rui-skills-client 默认分支](https://github.com/daguaid341-cpu/rui-skills-client)于 **2026-10-14** 的最新文档与 [`engine-manifest.json`](https://github.com/daguaid341-cpu/rui-skills-client/blob/ab6894e37f153feca07dfe2d13d5331cf3bb49fc/rui-skills/engine-manifest.json)更新，核对提交为 `ab6894e37f153feca07dfe2d13d5331cf3bb49fc`，引擎版本为 `2.0.1`。**新版安装与命令以该客户端为准；本仓库保留旧版实现和历史参考资料，此次 README 更新不代表旧代码已迁移。**

## v2.0.1 的主要变化

- **本地制作：**开源客户端调用闭源本地引擎。初次下载后，校验、导出、提示词生成与角色资产管理可离线运行，无需 Rui-Skills 设备凭证、管理员发放或在线版本审批。
- **精简提示词：**默认按镜头顺序输出，合并同一组内重复的摄影要求与适用备注，保留对白、关键动作、必要机位、视线和道具状态。完整资料与校验留在内部。
- **每组独立可用：**写清本组必要情境、角色关系、动作顺序、说话者、台词语言及完整台词，并列明具体声音和触发时机；生成 AI 无须依赖源剧本、其他组或聊天记录。
- **时长由内容决定：**按自然对白、连续动作和必要反应分配时长，每组不超过 30 秒，不预设组数和总片长。用户明确要求每组精确 30 秒时才使用 `--fixed-length`。
- **按叙事功能排镜：**先确定每镜需要让观众看见的信息，再选择景别、方向、正反打、焦点及必要运镜。特写只细化材料已有行为的情绪、眼神与语气，不为丰富镜头补造动作。
- **交付与语言：**默认最终交付 `.docx`；Markdown 是导出中间稿。镜头说明用中文，台词沿用源语言；源材料同时给出外语台词和中文释义时，提示词只保留完整外语台词。

详见新版[主技能](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/SKILL.md)、[提示词输出规则](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/references/prompt-output.md)、[叙事镜头设计](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/references/narrative-camera-design.md)与[节奏及交付规则](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/references/storyboard-pacing.md)。

## 功能模块

| 模块 | 产物与作用 |
| --- | --- |
| **大纲与已有大纲体检** | `novel-outline`：改编说明、人物表、戏剧节点、分集梗概与资产清单；检查结构、引用及节奏。改编范围服从用户授权，不凭书名补写未读内容。 |
| **人物资料** | `novel-characters`：角色卡、人物关系、来源依据、外形与音色提示词；实际出图和配音由当前可用工具另行执行。已有角色姓名在最终分镜中保留。 |
| **场景与道具资料** | `novel-art`：场景和叙事道具的辨识锚点、光照及状态变体、资产提示词；仅在用户委托资产设计时进入设计流程，已有剧本分镜不默认重设计布景。 |
| **剧本** | `novel-script`：场次、动作与台词节拍、按角色汇总的台词本及估算时长；实录配音后才可按音频验证台词用时。 |
| **真人剧分镜** | `novel-storyboard` 与真人剧模式：景别、实拍机位、正反打、焦点、已有动作与克制表演、光照、声音及剪切承接；保持人物身份、自然肤质与空间连续性。 |
| **漫剧分镜** | `novel-storyboard` 与漫剧模式：依据指定画风整理角色造型、线条、色板、关键姿态、虚拟镜头与运动；和真人剧分别维护项目及素材。 |
| **精简／完整提示词导出** | `export-text` 默认 `--detail compact --timing sequence`；`--detail full` 保留完整摄影字段并默认显示秒数；`--timing seconds` 可为精简稿单独显示时间。两种稿都保留完整台词并接受相同的时长校验。 |
| **校验与报告** | 本地检查 JSON 结构、资料引用、节拍覆盖、对白容量与时长，输出制作报告及模块 Markdown／HTML。程序校验不替代排镜审阅、实际配音或成片视觉验收。 |
| **人物三视图** | 在 `$rui-skills` 内使用人物工作流，依据当前指定参考图制作大头照＋正面、严格 90° 侧面、背面全身拼版提示词；需要图片时调用当前图像工具并实际验收。 |
| **角色参考资产管理** | 正面全身锚点、独立大头照／侧面／背面、单张重出、真实图片导入、历史版本及过期追踪；锚点或描述改变后标记旧派生图过期。 |
| **生成痛点反馈与预设更新** | 可选统计身份、肤质、裁切、角度、连续性和时长问题，按真实生成结果选择、试用及回退已有预设；指标、反馈、自动更新分别默认关闭。 |

正文由当前助手依据实际材料整理，本地引擎负责确定性校验、工作流与导出。**引擎不自带模型，不提供生图额度，也不执行视频生成或剪辑。**没有图像工具时只能交付人物提示词和待生成清单。

接口与字段见新版[制作数据契约](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/references/production-data.md)及[人物工作流](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/references/character.md)。

## 真人剧与漫剧

| 模式 | 使用场景 | 主要要求 |
| --- | --- | --- |
| **真人剧 / live-action** | 写实人物、真人短剧、实拍质感 | 人物身份与肤质、真实空间、摄影方向、受光关系、动作及微表演。 |
| **漫剧 / comic** | 漫剧、2D 动漫、国风／日漫或用户指定画风 | 造型与比例、线条、色板、关键姿态及虚拟镜头的一致性。 |

在请求中指定模式；已有项目沿用 `production.json`，没有项目配置时默认真人剧。镜头与动作说明默认中文，无字幕、无音乐／BGM；台词沿用源语言。用户本轮明确要求优先。

真人剧的共同摄影基准包括 9:16、ARRI ALEXA 35 的画幅参考、4K、24fps、180° 快门、自然肤色与轻微胶片颗粒。电影人像另参考 ARRI MINI、85mm f/1.2、Alexa 65 与 Panavision 的光学质感；这些是质感参考，单镜实际参数须自洽，按面部、道具和空间的信息需要调整景深。眨眼与微表情依据剧情自然安排，不设逐镜次数。漫剧仍服从用户指定画风。

30 秒是当前制作入口的组时长上限，不保证视频服务可一次生成 30 秒；投产时按实际服务上限在镜头边界拆分，同步时间、台词和末首帧状态。

## 使用示例

以下代码块是**用户调用示例**，不是已生成的最终提示词，也不代表已查看参考图或完成画面验收。

### 1. 真人剧：按动作安排紧凑分镜

```text
调用 $rui-skills，使用真人剧模式。
剧情：女生在餐桌上吃饭，听见门响后停下来，慢慢抬头看门口。
她表面平静，但已经开始紧张；表演克制。
仅将这段剧情分镜化，不增加人物、对白、道具或行为。
时长按动作自然完成来安排，每组不超过30秒，不必凑满。
交付可独立使用的精简提示词和Word文档；声音写明门响及其触发时机。
```

只有一句剧情也能开始，不强制提供整部剧本。需要而尚未明确的站位、手位或衔接，应提出最小必要问题。最终按「本组参考素材职责 → 统一风格与声音要求 → 逐镜描述 → 少量本组关键约束」整理；动作起点与承接放入相关镜头。

### 2. 漫剧：保持画风与关键姿态

```text
调用 $rui-skills，使用漫剧模式，画风为2D国风。
剧情：女生吃饭时听到门响，停下筷子，抬头看门口。
仅呈现上述动作，不增加人物、对白、道具或行为。
保持本次实际提交的角色造型和色板，写清关键姿态、取景与必要运动。
按实际动作分配时长，每组不超过30秒；门响在她停下筷子之前发生。
交付精简提示词和Word文档，无字幕、无BGM。
```

真人与漫剧使用各自的素材和提示词。切换模式后先整理对应资料，不把真人摄影参数机械复制为漫剧画风。

### 3. 完整摄影稿：需要逐镜核对拍法时

```text
调用 $rui-skills，使用真人剧模式。
剧情：女生在餐桌上吃饭，听见门响后停下来，慢慢抬头看门口。
她表面平静，但已经开始紧张；表演克制。
仅呈现这段剧情，不增加人物、对白、道具或行为。
本次交付完整摄影稿和Word文档，保留必要机位、景别、焦点与动作承接，显示秒数。
每组仍按实际动作安排，不超过30秒；门响在她停止吃饭之前发生。
```

完整稿用于审阅摄影和时间，精简稿用于减少同组重复指令；两种稿使用同一份资料，不删台词、不改动作顺序。

### 4. 已有剧本：保留姓名与台词语言

```text
调用 $rui-skills，将本次随请求提供的剧本整理为真人剧分镜。
保留剧本中的角色实名、动作对象、视线顺序和道具归属。
逐句保留台词；剧本同时列出外语台词与中文释义的部分，只输出外语台词。
最终每组写出具体动作、必要情境、说话者、台词语言、完整台词、具体声音和触发时机。
每组单独提交时均能理解，不依赖其他组、源剧本或完整人物小传。
按自然对白和动作分配时长，交付精简提示词和Word文档。
```

“保留原文、逐字核对”等要求用于内部审核；最终生成指令直接列出本组动作和台词，不用这些指代替代实际内容。

### 5. 小说与完整项目：按委托范围进入模块

```text
调用 $rui-skills，将本次随请求提供的小说材料整理为2D国风漫剧项目。
先给出基于已读材料的大纲与结构检查，再整理人物、场景、道具和剧本资料。
改编范围以本次明确要求为准；未授权的剧情、角色和台词调整先列为待确认项。
将已确定的剧本分镜化，保留来源和角色实名，不为凑满30秒增加内容。
交付可检查的结构化资料、制作报告及按实际时长分组的Word分镜。
```

项目资料按任务需要提供，无须为单场分镜补做整部大纲：

```text
project/
├── production.json
├── outline/outline.json
├── characters/cast.json
├── art/art.json
├── script/script.json
└── storyboard/storyboard.json
```

`production.json` 可使用 `{"mode":"live-action"}` 或 `{"mode":"comic","style":"2D国风，清晰线稿、统一色板"}`。`--mode` 只选择本次检查或导出模式，不自动改编剧本或绘制资产。

### 6. 人物三视图与独立参考资产

```text
调用 $rui-skills，处理人物三视图。
使用本次随请求提交的人物参考图，先实际查看再记录可见事实。
保留人物身份、脸部、发型与衣饰，生成大头照＋正面、严格90°侧面、背面全身拼版。
需要说明的不可见部位推断单独标明；出图后实际检查身份、比例和角度。
```

```text
调用 $rui-skills，为本次提交的角色参考图建立独立图片资产，使用写实风格。
先生成并验收正面全身锚点，再派生大头照、侧面与背面。
保留版本；锚点或描述改变后标记旧派生图过期，并按需要单张重出。
```

v2.0.1 在 `$rui-skills` 内提供人物工作流。只要提示词时不调用生图；需要图片时，将真实参考图传给当前可用图像工具，再导入与验收实际结果。人物资产和视频分镜分开交付，通过指定素材衔接。

## 新版安装与命令

从 [rui-skills-client](https://github.com/daguaid341-cpu/rui-skills-client)获取完整 `rui-skills/` 目录，安装到支持本地技能的环境。不要仅复制 README 或 `SKILL.md`。当前已验证的本地引擎为 **Windows x64 / Node.js 24.15.0**，运行版本必须与清单一致。

以下命令均在**新版客户端的 `rui-skills/` 技能目录**执行；输出路径需使用新文件名，导出不会覆盖已有文件。

```powershell
node scripts/install-engine.mjs
node scripts/production.mjs check "C:/Projects/My Drama"
node scripts/production.mjs report "C:/Projects/My Drama" --out "C:/Projects/My Drama/reports-v201"
node scripts/production.mjs export-text "C:/Projects/My Drama" --out "C:/Projects/My Drama/storyboard/精简提示词-v201.md"
node scripts/production.mjs export-text "C:/Projects/My Drama" --detail full --out "C:/Projects/My Drama/storyboard/完整摄影稿-v201.md"
node scripts/production.mjs export-text "C:/Projects/My Drama" --timing seconds --out "C:/Projects/My Drama/storyboard/带时间提示词-v201.md"
node scripts/production.mjs run novel-outline checkup "C:/Projects/My Drama/outline/outline.json"
node scripts/character.mjs workflow turnaround
node scripts/character.mjs workflow assets
```

安装器从客户端仓库 Release 下载闭源引擎，按清单逐文件核对 SHA-256。初次下载需要网络，后续本地制作不依赖云端；校验摘要不是在线授权。实际图像工具的网络与输入处理规则由该工具自身决定。

`--variable-length` 保留为兼容选项，默认已是可变时长；用户明确要求每组精确 30 秒时才加入 `--fixed-length`，两者不可同时使用。文本导出后仍需按字段自然分段整理为最终 Word，段内自动折行，不插入按页面宽度截断的手动换行。

## 交付与验收规则

- **来源与人物：**只声称读过实际提供的材料；最终逐镜沿用角色实名，写清谁执行动作、谁说话、谁看向谁及道具归属，不把内部通用身份或编号直接当作最终人物称谓。
- **素材与空间：**默认按参考图齐全的前提精简写作，但这不证明已查看或已上传图片。只引用真实提交的素材，不虚构编号或绑定，不重新设计已有外观和布景；投产必需而未明确的位置或手位先询问。
- **表演与镜头：**按材料细化已有行为，保留知情范围；不新增动作、回忆或后续真相。画面描述不用生理变色表达情绪，台词中的原句仍逐字保留。摄影参考写一次，必要机位、正反打与焦点保留到镜头正文。
- **连续性与声音：**位置、轴线、手位、道具状态、动作起点及剪切承接写入相关镜头，统一提示词不含人物站位。每组明确实际事件的声源与触发时机，避免声音、运动、焦点及曝光要求相互冲突。
- **验收状态：**分别报告文本／结构校验、实际配音测试和成片／图像视觉验收。未执行的检查不标为通过，只有提示词时不声称已出图或画质提升。

## 可选反馈与更新

运行指标、真实生成结果反馈、自动预设更新**分别默认关闭**，仅开启用户明确同意的项目。反馈只提交固定类别、结果、尝试档位及是否采用增强预设，不提交图片、剧情、聊天、路径、姓名或自由文本；本地原始日志不自动上传。

每次实际生成后查看结果，记录成功或失败；失败后定向调整，默认每项任务最多 3 次实际生成尝试，更多次数须有用户明确预算。云端只选择、试用、比较与回退已经实现的预设，不接模型、不训练权重、不生成任意新代码，也不保证视觉质量必然提升。云端不可用不阻断本地制作。

控制与隐私细节见新版[反馈闭环](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/references/learning-loop.md)和[本地运行与隐私](https://github.com/daguaid341-cpu/rui-skills-client/blob/main/rui-skills/references/local-verification.md)。
